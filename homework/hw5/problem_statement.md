# Домашнее задание №5

## Хранение данных и согласованность

Цель: спроектировать хранение агрегата с оптимистичной блокировкой, реализовать распределённую сагу для сквозных бизнес-процессов и обеспечить идемпотентную обработку событий.

## Описание/Пошаговая инструкция выполнения домашнего задания:

## Инструкция:

1. Маппинг в БД: Возьмите ваш агрегат Order и спроектируйте его хранение в реляционной БД (PostgreSQL). Напишите DDL-скрипты (CREATE TABLE... ) для всех необходимых таблиц. Объясните, как вы сохранили Value Objects.

2. Оптимистичные блокировки: Добавьте в таблицу Orders поле Version. Опишите (или покажите в псевдокоде SQL), как будет выглядеть запрос UPDATE, реализующий механизм оптимистичной блокировки для предотвращения «потерянных обновлений».

3. Проектирование Саги (Saga):

- Спроектируйте распределённый бизнес-процесс «Оформление и оплата заказа», затрагивающий минимум 3 контекста (например, Orders, Payments, Notifications).
- Опишите по шагам позитивный сценарий (happy path).
- Опишите компенсирующие транзакции для негативного сценария (например, если оплата не прошла после создания заказа).

4. Идемпотентный обработчик: Напишите псевдокод обработчика события OrderPaidEvent на стороне сервиса Notifications. В нём должна быть реализована логика идемпотентности (например, через проверку в БД уже обработанных ID событий), чтобы уведомление не отправлялось дважды.

## Формат сдачи:

Текстовый документ (Markdown) с скриптами SQL, описанием шагов Саги и псевдокодом обработчика. Допускается сдача в виде файлов в репозитории проекта.

При отправке ссылки, убедитесь, что по ней открыт доступ.


Если у вас возникнут вопросы, вы можете задать их в чате проверки домашнего задания или в VK-группе.

## Критерии оценки:

Статус «Принято», если:

1- Персистентность: Корректность сохранения Value Objects и коллекций агрегата в реляционную структуру БД.
2- Конкурентный доступ: Понимание механизма оптимистичной блокировки и предотвращения lost updates.
3- Распределённые транзакции: Полнота описания шагов Саги, особенно проработка негативных сценариев и компенсирующих транзакций.
4- Надёжность: Правильная реализация логики идемпотентности в обработчике.
